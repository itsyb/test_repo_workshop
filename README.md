# PMI DNA: The Gem Quest

Внутрішня платформа peer-recognition для команди (до 100 учасників): колеги дарують один одному гени за поведінку відповідно до цінностей PMI DNA, накопичують їх і обмінюють у DNA Store.

**Стек:** Next.js 15 (App Router, Server Actions) · TypeScript · Tailwind CSS 4 · Motion (анімації) · Prisma + SQLite (легко переключається на Postgres).

## Швидкий старт

```bash
npm install
cp .env.example .env          # налаштування — див. нижче
npx prisma db push            # створює БД (prisma/dev.db)
npm run db:seed               # учасники з data/users.csv + каталог магазину + ідеї челенджів
npm run dev                   # http://localhost:3000
```

Демо з наповненою стрічкою: у `.env` поставте `PROGRAM_START` на понеділок у минулому (наприклад `2026-09-28`) і виконайте `npm run db:seed -- --demo`.

Вхід — за посиланням на email. Поки `AUTH_DEV_LINKS="true"`, посилання показується одразу на екрані (лише для локального запуску й демо). Для продакшну вимкніть цей прапорець і задайте `SMTP_URL`.

## Статичне демо (GitHub Pages)

Інтерактивна версія без сервера для швидких показів: **https://itsyb.github.io/test_repo_workshop/**

- Замість входу вибираєте одну з 4 демо-персон: Executive/Admin, Lead, Manager, Member.
- Дані (22 вигадані учасники, 2 завершені спринти історії, банк, челенджі, замовлення) генеруються і зберігаються **тільки у вашому браузері** (localStorage). У кожного глядача свій незалежний світ; «Reset demo data» в меню аватара починає все заново.
- Правила ті самі, що й у повній версії: обидві викликають `src/lib/rules.ts`.
- Демо-учасники задані в `src/demo/fixture.ts` і не пов'язані з `data/users.csv`, тож реальні імена на Pages не потраплять.

Як це влаштовано: `DEMO_STATIC=1` вмикає `output: "export"` і змушує Next.js бачити тільки файли маршрутів `*.demo.tsx` (`src/app/(demo)/…`, `src/app/login/page.demo.tsx`, `src/app/layout.demo.tsx`). Сторінки обох версій рендерять ті самі view з `src/views`; різниться лише джерело даних (Prisma + server actions або `src/demo/engine.ts`).

```bash
DEMO_BASE_PATH=/test_repo_workshop npm run build:demo   # → out/
```

Деплой робить `.github/workflows/demo-pages.yml` на кожен пуш. Один раз потрібно ввімкнути: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

## Правила програми (реалізовано)

| Правило | Де в коді |
|---|---|
| Спринт = 2 тижні, понеділок 00:00 → неділя 23:59 (Europe/Kyiv, з урахуванням переходу на зимовий час). Перший спринт — `PROGRAM_START` (за замовчуванням 12.10.2026). Свята й відпустки не пропускаються. | `src/lib/time.ts` |
| На старті спринту кожен отримує **2 прозорі** гени; Lead і Manager — ще **по 1 жовтому за кожного прямого підлеглого**. | `src/lib/sprint.ts` → `allocate` |
| Прозорий гем під час дарування стає Blue / Purple / Green. **Не більше одного прозорого одній людині за спринт.** Собі дарувати не можна. | `src/lib/give.ts` |
| Жовтий — тільки від свого керівника (Lead/Manager), **1 на підлеглого за спринт**. | `src/lib/give.ts` |
| Коментар обов'язковий для будь-якого дарування, **мінімум 20 символів**; усе потрапляє в публічну стрічку. | `src/lib/give.ts`, `/feed` |
| Скасувати подарунок **не можна**. | — |
| Наприкінці спринту невикористані гени **згорають у SFP Bank** («Missed Opportunities») із збереженням кольору. Отримані гени не згорають. | `src/lib/sprint.ts` → `closeSprint` |
| Новачок, доданий посеред спринту, отримує гени **з наступного спринту**. | `src/lib/sprint.ts` |
| Бонус першого спринту: +1 Purple тим, хто роздав усі гени. | `closeSprint` |
| У магазині **всі кольори мають однаковий номінал**; користувач сам обирає, якими генами платити (або «Auto-pick»). Відхилене замовлення повертає гени. | `src/lib/store.ts` |
| Одночасно активні **не більше 2 челенджів**; призи виплачуються адміном із SFP Bank. | `src/lib/challenges.ts` |

Спринти відкриваються й закриваються автоматично під час першого запиту після межі спринту, тож cron не потрібен.

## Учасники

Учасники додаються **тільки напряму через базу даних**, реєстрації немає.

- Початкове завантаження: заповніть `data/users.csv` (`email,name,role,managerEmail,title,team,isAdmin`; `role` — `EXECUTIVE | LEAD | MANAGER | MEMBER`) і виконайте `npm run db:seed`. Команду можна повторювати, записи оновлюються за email.
- Подальші зміни: `npm run db:studio` → таблиця `User` (`managerId` — id керівника, `active=false` — вимкнути учасника).

## Сторінки

- `/` — головна: гени до роздачі, колекція, таймер спринту, челенджі, остання стрічка.
- `/give` — дарування гема (тип → колір → отримувач → коментар) з анімацією відправки.
- `/feed` — публічна стрічка з фільтром за кольором.
- `/challenges` — активні челенджі, подача заявок, зала слави.
- `/store` — DNA Store і оформлення замовлення.
- `/people`, `/people/[id]` — люди, профіль, колекція, замовлення (свої).
- `/admin` — огляд спринту, SFP Bank, замовлення, челенджі (активація, призи), товари, список учасників. Доступ має `isAdmin=true`.

## Продакшн

1. Postgres: у `prisma/schema.prisma` змініть `provider = "postgresql"` і задайте `DATABASE_URL`.
2. `SMTP_URL`, `MAIL_FROM`, `APP_URL`; `AUTH_DEV_LINKS="false"`.
3. `npm run build && npm start` (або будь-який хостинг Next.js).
